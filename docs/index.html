What this measures

  • Compression ratio = compressed bytes / fp32 bytes of the conv+linear weights (honest byte counts: bitmask/index overhead, codebooks, U+V, etc.). Lower = more compressed. BatchNorm/biases are kept dense and excluded from both sides.
  • Recovery = reaching test accuracy within 0.5 pp of baseline on the full 10k test set.
  • Recovery fraction = retraining steps used / baseline steps. Capped at 10% (20 epochs vs the 200-epoch baseline); a run that doesn't reach the bar in that budget is DNR. Reconstructed weights are used as a dense init and retrained with the same recipe.

Headline findings

  • 12 of 63 (technique, knob) runs recovered to within 0.5 pp of the 90.08% baseline within the 10% retraining budget; the rest are DNR (did not recover in budget).
  • Most aggressive compression that still recovers: quantize_1_distill at compression ratio 0.031 (≈32× smaller), recovered using 8.5% of baseline training cost.
  • Cheapest recovery: kmeans_6_fine bounced back in only 0.1% of the original training cost (near-lossless reconstructed init).
  • Techniques with at least one recovery: additive_vq, kmeans, magnitude_prune, quantize.
  • Techniques that never recovered in budget: fisher_prune, low_rank, magprune_quant, random_sparse, snip — these destroy weight structure (zeroing / low-rank), and 20 epochs is not enough to climb back.
