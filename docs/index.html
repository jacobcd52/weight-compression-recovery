What this measures

  • Compression ratio = compressed bytes / fp32 bytes of the conv+linear weights (honest byte counts: bitmask/index overhead, codebooks, U+V, etc.). Lower = more compressed. BatchNorm/biases are kept dense and excluded from both sides.
  • Recovery = retraining (dense-from-init, plain CE) until the full-test cross-entropy drops below the baseline's own test loss. The baseline is deliberately undertrained (50 epochs) so it is not overfit and this target is well-posed.
  • Recovery cost = retraining steps used / baseline steps, capped at 10%; a run that doesn't reach the bar in that budget is DNR.
  • Amortized ratio (2nd plot) removes the size-independent codebook/scale overhead to approximate the ratio at large model size.

Headline findings

  • 3 of 30 (technique, knob) runs recovered — i.e. retrained to a full-test loss below the baseline's 0.402 within the 10% budget; the rest are DNR (did not recover in budget). Recovery metric = test loss.
  • Most aggressive compression that still recovers: additive_vq_4_8_8 at compression ratio 0.140 (≈7× smaller), recovered using 8.2% of baseline training cost.
  • Cheapest recovery: kmeans_6 bounced back in only 0.3% of the original training cost (near-lossless reconstructed init).
  • Techniques with at least one recovery: additive_vq, kmeans, quantize.
  • Techniques with no recovery in budget: aqlm, magnitude_prune, magprune_quant.
  • The amortized plot below re-counts the compression ratio without the size-independent codebook/scale overhead (a large fixed cost on a 270k-param model) — approximating the ratio at large model size, which especially helps the vector-quantization methods (k-means, additive_vq, AQLM).

Pareto frontier — honest bytes

x = compression ratio (log, left = more compressed); y = fraction of original training cost needed to recover (log, lower = cheaper). Open markers at the top = DNR. Circles = plain, triangles = distillation. Black line = Pareto frontier.

Pareto frontier — amortized (large-model proxy)

Same as above but the x-axis counts only per-weight bytes (codes/values/indices), dropping the size-independent codebook and scale overhead that dominates on a tiny 270k-param model. This is the ratio the vector-quantization methods would approach at large model size.

Recovery dynamics vs. LR / schedule (diagnostic)

Why the headline recovery cost (~7%) is partly an LR artifact: the near-lossless init (quantize_8, left) recovers in ~0.2% at a gentle constant LR (3e-5) but ~6.7% under the high-LR cosine — a ~33x inflation. The harder init (kmeans_2, right) instead needs the cosine anneal-to-zero to dip below baseline. So recovery cost should be measured as the minimum over a small LR/schedule grid.
